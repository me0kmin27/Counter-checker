# Counter Checker 사용 방법

이 문서는 Debian 설치 완료 후 POP 계정을 등록하고 수신 메일을 확인하는 과정을 설명합니다.
현재 버전은 메일 수신·저장·조회까지만 지원하며 OCR 및 카운터 분석은 아직 실행하지 않습니다.

## 1. 웹 화면 접속

설치 과정에서 입력한 도메인 또는 서버 IP를 브라우저 주소창에 입력합니다.

```text
http://<설치할 때 입력한 도메인 또는 서버 IP>
```

예를 들어 설치 단계에서 `counter.example.invalid`를 입력했다면 접속 형식은
`http://counter.example.invalid`입니다. 이 주소는 형식을 설명하기 위한 예약 예시이며,
실제로는 설치 환경의 도메인 또는 IP를 사용해야 합니다.

로그인 화면에서 설치 스크립트 실행 중 입력한 **웹 관리자 아이디**와 **웹 관리자 비밀번호**를
사용합니다. MariaDB 관리자 계정이나 POP 계정으로는 웹에 로그인할 수 없습니다.

## 2. POP 계정 등록

로그인 후 왼쪽 메뉴의 **POP 설정**을 선택하고 다음 값을 입력합니다.

| 항목 | 입력 내용 |
| --- | --- |
| 표시 이름 | 화면에서 계정을 구분할 이름입니다. 고객명이나 실제 이메일 주소 대신 운영용 별칭을 사용할 수 있습니다. |
| POP 서버 | 메일 서비스에서 안내하는 POP3 서버 호스트 이름 또는 IP입니다. |
| 포트 | POP3S는 일반적으로 `995`, 암호화하지 않는 POP3는 일반적으로 `110`을 사용하지만 실제 값은 메일 서비스 설정을 확인해야 합니다. |
| TLS 사용 | 서버가 POP3S를 지원하면 선택합니다. 운영 환경에서는 TLS 사용을 권장합니다. |
| 사용자 이름 | POP 서버 인증에 사용하는 계정입니다. 메일 서비스에 따라 전체 이메일 주소일 수 있습니다. |
| 비밀번호 | POP 비밀번호 또는 메일 서비스에서 발급한 애플리케이션 비밀번호입니다. 저장할 때 암호화됩니다. |
| 자동 수신 활성화 | 선택하면 cron 수신 대상에 포함됩니다. |
| 수신 후 서버에서 삭제 | 선택하면 정상 조회한 메시지에 POP `DELE` 명령을 실행합니다. 초기 운영에서는 선택하지 않는 것을 권장합니다. |

입력을 마친 뒤 **계정 저장**을 누릅니다. 저장된 POP 비밀번호는 웹 화면에 다시 표시되지
않으므로 비밀번호 변경이 필요하면 기존 계정을 비활성화하거나 삭제한 후 다시 등록합니다.

> 메일 제공자 측에서도 POP 사용이 활성화되어 있어야 합니다. 다단계 인증을 사용하는
> 서비스는 일반 로그인 비밀번호 대신 별도의 애플리케이션 비밀번호가 필요할 수 있습니다.

## 3. 최초 연결 확인

등록 계정 오른쪽의 **지금 받기**를 누릅니다.

- 성공하면 새로 저장한 메일 건수가 상단 알림에 표시됩니다.
- 이전에 받은 것과 원문이 같은 메일은 중복 저장하지 않으므로 `0건`으로 표시될 수 있습니다.
- 실패하면 계정 아래와 상단 알림에 POP 서버가 반환한 오류가 표시됩니다.
- 메일 한 건의 원문 크기가 25MB를 초과하면 해당 수신 작업은 오류로 기록됩니다.

연결이 실패하면 다음 항목을 순서대로 확인합니다.

1. POP 서버 주소와 포트가 메일 서비스 설정과 일치하는지 확인합니다.
2. TLS 지원 서버인데 **TLS 사용**을 해제하지 않았는지 확인합니다.
3. 사용자 이름 및 비밀번호 또는 애플리케이션 비밀번호가 올바른지 확인합니다.
4. 메일 제공자 설정에서 POP 접근이 허용되어 있는지 확인합니다.
5. Debian 서버에서 POP 서버의 해당 포트로 나가는 방화벽 연결이 허용되는지 확인합니다.
6. TLS 인증서 오류라면 서버 시간이 정확한지, POP 서버 인증서가 유효한지 확인합니다.

## 4. 받은 메일 확인

왼쪽 메뉴에서 **받은 메일**을 선택합니다. 목록에는 제목, 보낸 사람, 수신한 POP 계정,
첨부 개수 및 수신 시각이 표시됩니다.

메일 제목을 선택하면 다음 내용을 확인할 수 있습니다.

- 보낸 사람과 받는 사람
- 메일을 수신한 POP 계정
- 수신 시각
- 텍스트 본문
- 첨부 파일 이름, MIME 유형 및 크기

첨부 파일을 선택하면 로그인한 관리자 세션을 통해 다운로드합니다. HTML 본문은 외부 이미지나
스크립트를 실행하지 않도록 현재 화면에서 직접 렌더링하지 않고 텍스트 본문만 표시합니다.

## 5. 자동 수신 확인

설치 스크립트는 다음 cron 작업을 `/etc/cron.d/counter-checker`에 등록합니다.

```text
5분마다 → 활성화된 모든 POP 계정 확인 → 신규 메일 저장
```

서버에서 즉시 수신 작업을 실행하려면 저장소 디렉터리에서 다음 명령을 사용합니다.

```bash
sudo -u www-data \
  COUNTER_CHECKER_CONFIG=/etc/counter-checker/config.php \
  php scripts/fetch-mail.php
```

자동 수신 로그는 다음 명령으로 확인합니다.

```bash
sudo tail -f /var/log/counter-checker-mail.log
```

각 계정의 마지막 오류는 웹의 **POP 설정** 화면에서도 확인할 수 있습니다. 오류 원인 수정 후
**지금 받기**를 다시 실행하면 성공 시 기존 오류 표시가 제거됩니다.

## 6. 계정 중지 또는 삭제

POP 설정에서 계정 오른쪽의 `×` 버튼을 누릅니다.

- 아직 수신한 메일이 없는 계정은 삭제됩니다.
- 이미 수신한 메일이 있는 계정은 기존 메일과의 연결을 보존하기 위해 삭제하지 않고
  자동 수신만 비활성화합니다.

**수신 후 서버에서 삭제**를 사용한 계정은 POP 세션이 정상 종료될 때 서버 측 삭제가
확정될 수 있으므로, 보존 정책과 백업을 확인한 뒤 사용해야 합니다.

## 7. 저장 위치 및 운영 점검

| 데이터 | 기본 저장 위치 |
| --- | --- |
| 실행 설정 및 비밀값 | `/etc/counter-checker/config.php` |
| 메일 원문과 첨부 | `<저장소>/var/mail/YYYY/MM/` |
| 메일 메타데이터와 본문 | 설치 시 지정한 MariaDB 데이터베이스 |
| 자동 수신 로그 | `/var/log/counter-checker-mail.log` |
| Nginx 사이트 설정 | `/etc/nginx/sites-available/counter-checker` |
| cron 설정 | `/etc/cron.d/counter-checker` |

운영 시작 전에는 다음 사항을 적용하는 것이 좋습니다.

1. Nginx에 유효한 TLS 인증서를 설정합니다.
2. `/etc/counter-checker/config.php`의 `app_url`을 `https://` 주소로 바꿉니다.
3. 같은 설정 파일의 `session_secure`를 `true`로 바꿉니다.
4. 설정 파일, MariaDB 및 `var/mail`을 함께 백업합니다.
5. 메일 원문과 첨부 파일의 보존 기간 및 삭제 절차를 정합니다.
6. `/etc/counter-checker/config.php`가 Git이나 공개 백업에 포함되지 않도록 확인합니다.

설정 변경 후에는 다음 명령으로 Nginx 설정을 확인하고 다시 불러옵니다.

```bash
sudo nginx -t
sudo systemctl reload nginx
```
